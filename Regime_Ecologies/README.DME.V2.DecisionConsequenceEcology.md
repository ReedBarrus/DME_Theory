## 1. Purpose

This document defines the Decision / Consequence Ecology of DME V2.

Decision / Consequence Ecology is one of the two primary runtime coordinate regimes derived from Distinction Space.

It explains how distinction topology branches into:

```text
possible transitions
simulated branches
blocked branches
permitted branches
execution candidates
realized consequences
feedback
repair
contestation
revocation
future constraints
```

This is not a generic decision theory document.

It defines a navigable, governable, actionable topological framework for applying DME to real systems.

Decision / Consequence Ecology is where distinction topology becomes consequential under provenance, agency, admissibility, budget, authority, and feedback.

---

## 2. Core Thesis

```text
Decision / Consequence Ecology is the geometry of how distinction topology branches
into permitted action, realized consequence, feedback, repair, revocation, and future constraint.
```

Compressed:

```text
Distinction = what can matter.
Agency = who/what can attend, interpret, request, act, or be affected.
Decision = what can branch, execute, change, repair, or revoke.
Consequence = what changed after execution.
Feedback = what returns from consequence.
Integration = how returned signal updates future topology.
```

Core law:

```text
Decision is branchable transition topology.
Consequence is realized decision topology.
```

## 5. Decision Lifecycle

Decision is staged geometry.

A decision does not appear all at once.

Canonical lifecycle:

```text
AttentionEnvelope
+ DecisionRelevance
+ Agentic Intention
+ Budget / Admissibility
→ DecisionPressure
→ DecisionEnvelope
→ BranchTopology
→ Simulation / Projection
→ AdmissibilityCheck
→ Consent / Stake / Authority Check
→ ExecutionCandidate
→ Execution
→ ExecutionReceipt
→ ConsequenceSignature
→ FeedbackRecord
→ IntegratedConsequenceRecord
→ Repair / Retention / Proof / Authority / Reference Route
→ ProvenanceTopology
```

The full lifecycle begins upstream in distinction and agency:

```text
DistinctionEnvelope
→ DistinctionRegion
→ Distinction-State
→ ProjectionHandle / ObserverFrame
→ AttentionEnvelope
→ Request / Intention Pressure
→ DecisionEnvelope
```

With:

```text
ProvenanceEnvelope running through all stages.
```

## 14. Execution vs Consequence

Execution and consequence must remain separated.

```text
Execution = effect emission.
Consequence = realized change.
```

Execution can succeed technically while consequence fails coherently.

Example:

```text
email sent successfully
→ execution success

recipient misunderstands / wrong attachment sent / harm occurs
→ consequence rupture
```

Core law:

```text
Execution success ≠ consequence success.
```

## 24. Decision / Consequence Metric Families

No formal metrics are defined yet.

However, DME should preserve the following metric families for future schemas.

### Branch Support

How strongly distinctions support a branch.

### Agentic Pressure

How much request, attention, intention, or stake pressure supports movement.

### Stake Clarity

How clearly affected loci and consequence exposure are represented.

### Admissibility Status

Whether transition may proceed, defer, quarantine, or route.

### Authority Ceiling

How much consequence capacity is allowed.

### Consent Validity

How well consent preserves scope, stake, projected consequence, and revocation.

### Simulation Fidelity

How well simulation represents likely consequence.

### Reversibility

How easily consequence can be repaired, rolled back, or revoked.

### Execution Readiness

How prepared a branch is for effect emission.

### Consequence Risk

How severe, uncertain, or irreversible the consequence may be.

### Feedback Availability

How well feedback can be observed, delayed, inferred, or requested.

### Repairability

How feasible coherent repair is after rupture.

### Provenance Fidelity

How well lineage, lens, loss, operator path, and reconstruction conditions are preserved.

### Ledger Completeness

How well accountable decision/consequence history can be reconstructed.

### Trust Impact

How consequence integration affects trust evidence.

### Reference Potential

Whether coherent scoped consequence supports future guidance.
