## 1. Purpose

This document defines the Feedback / Integration Ecology of DME V2.

Feedback / Integration is a cross-cutting support regime.

It governs how consequence returns into future topology.

It answers:

```text
What returned from consequence?
What changed?
What matched expectation?
What ruptured expectation?
What should integrate?
What should repair?
What should release?
What should route to proof?
What should affect retention?
What should affect budget?
What should affect trust, authority, or reference?
```

This ecology closes the loop between decision, consequence, runtime, memory, and future configuration.

It is the reality-coupling regime of DME.

---

## 2. Core Thesis

```text
Feedback / Integration Ecology is the reality-coupling regime:
what returns from consequence, how coherence delta is detected,
and how future topology is updated.
```

Compressed:

```text
Feedback = what returns from consequence.
Integration = how returned signal updates future topology.
CoherenceDelta = difference between expected consequence and returned consequence.
Repair = route for restoring coherence after rupture.
Release = route for stopping stale or unsupported pressure.
```

Core law:

```text
No decision lifecycle is complete at execution.
Decision lifecycle closes only through consequence feedback and integration.
```

---

## 3. Why Feedback / Integration Exists

DME should not trust action merely because it executed.

Execution only proves that an effect was emitted into a target regime.

Feedback determines what returned.

Integration determines what that return means for future topology.

Without Feedback / Integration, DME risks collapse such as:

```text
execution success → consequence success
positive feedback → legitimacy
negative feedback → invalidation
memory echo → current truth
tool output → reality
test pass → global correctness
user silence → consent
```

Feedback / Integration prevents these collapses by requiring returned consequence to be bounded, compared, interpreted, integrated, and ledgered.

```text
Feedback =
```


Feedback is not truth.

```text

positive_feedback ≠ authority
negative_feedback ≠ invalidation
absence_of_feedback ≠ success
```

## 13. Integration Outcomes

Canonical outcome set:

```text

archive
quarantine
route_to_proof
route_to_governance
route_to_revocation

update_reference_candidate

```

### strengthen

Feedback increases support under declared scope.

### weaken

Feedback decreases support under declared scope.

### confirm_under_scope

Feedback matches expectation within declared limits.

### contradict_under_scope

Feedback conflicts with expectation within declared limits.

### repair

Feedback indicates coherence restoration is needed.

### release

Feedback indicates active pressure should stop.

### retain

Feedback indicates state should persist or re-enter later.

### archive

Feedback indicates lineage should remain but not active pressure.

### quarantine

Feedback indicates unsafe or uncertain normal re-entry.

### route_to_proof

Feedback indicates load testing is required.

### route_to_governance

Feedback indicates higher review is required.

### route_to_revocation

Feedback indicates access, authority, consent, retention, or reference should be reduced.

### update_budget

Feedback changes future capacity.

### update_authority

Feedback changes scoped consequence capacity.

### update_reference_candidate

Feedback changes future guidance status.

### no_update

Feedback is too weak, ambiguous, irrelevant, or out of scope.

```text

→ trust evidence delta
→ authority review
→ authority ceiling modulation
```

```text
Authority grows only through integrated coherent consequence under scope,
```

Authority may decay through:


Non-collapse:

```text
trust ≠ authority
```
