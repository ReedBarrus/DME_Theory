## 1. Purpose

This document defines the runtime regime lifecycle of DME V2.

It explains how DME's regimes organize the lifecycle of distinctions across the four substrates:

```text
Structure
Runtime
Ledger
Projection / Index / Rasterization
```

This document exists to prevent regime sprawl.

Regimes are not separate worlds.

Regimes are layered coordinate spaces over the configuration-attention continuum.

They describe how distinctions become active, agentic, decision-bearing, consequential, remembered, tested, governed, referenced, and recursively reused.

---

## 2. Core Thesis

```text
DME regime ecology is organized into layered coordinate spaces over the configuration-attention continuum.
```

The root operational regime is:

```text
Distinction Space
```

The primary runtime coordinate regimes are:

```text
Agentic Space
Decision Space
```

The cross-cutting support / conservation / governance regimes are:

```text
Projection Space
Ledger / Provenance Space
Retention Space
Proof Space
Budget / Admissibility Space
Authority / Reference Space
Feedback / Integration Space
```

Derived lifecycle dynamics such as expectation, belief, intention, consent, execution, consequence, trust, access, repair, contestation, revocation, and canon emerge within and between those regime layers.

Core compression:

```text
Distinction = what can matter.
Agentic = what can attend, interpret, request, act, or be affected.
Decision = what can branch, execute, change, repair, or revoke.

Projection = what can be addressed.
Ledger / Provenance = what can be reconstructed.
Retention = what can persist or re-enter.
Proof = what can survive load.
Budget / Admissibility = what can proceed under constraint.
Authority / Reference = what can affect consequence or guide future configuration.
Feedback / Integration = what returns from consequence into future topology.
```

Core law:

```text
Regime ≠ substrate.
Regime = lifecycle coordinate space over substrates.
```

## 3.X. Distinction Space as Functional Continuum

The configuration-attention continuum becomes operational through distinction space.

```text
Distinction is the core unit of configuration-attention topology.
```

A distinction is not merely a noticed difference.

```text
A distinction is a bounded, supported difference in configuration space that can receive attention,
enter relation, become projected, influence decisions, be retained, be proof-tested,
and participate in consequence.
```

Distinction space is therefore the functional expression of the configuration-attention continuum.

It is where source-derived configuration becomes selectable under attention.

It is where differences become active enough to relate, recur, project, branch, persist, or release.

Distinction space bridges:

```text
source signal
structural support
runtime attention
projection handles
symbolic tokens
decision branches
retention echoes
proof targets
authority constraints
reference candidates
```

This makes distinction more fundamental to DME than vague terms like thought, fact, memory, or node.

A thought may contain attention, imagery, memory, emotion, language, expectation, belief, or intention.

A distinction identifies the functional operation underneath:

```text
this differs from that
this boundary matters
this pattern recurs
this relation holds
this branch becomes possible
this consequence may follow
```

In DME, regimes coordinate the lifecycle of distinctions.

A distinction may appear as:

```text
structural support
runtime activity
projection handle
belief support
decision branch
retention candidate
proof target
authority constraint
reference candidate
```

These are not separate realities.

They are different regime coordinates over the same distinction topology.

Core law:

```text
Distinction space is the operational surface of the configuration-attention continuum.
```

Non-collapse laws:

```text
distinction ≠ raw difference
distinction ≠ token
distinction ≠ thought
distinction ≠ truth
distinction ≠ proof
distinction ≠ authority
distinction_space ≠ projection_space
```

## 4. Regime Hierarchy

DME regimes are not all peer-level.

The regime ecology has four layers:

```text
Layer A — Root Operational Regime
```

This hierarchy prevents the system from inflating every useful dynamic into a competing root architecture.

## 5. Lifecycle Flow Across the Regime Hierarchy

The lifecycle flow is not a flat list of peer regimes.

It is the movement of distinctions through agentic and decision coordinates, regulated by projection, ledger/provenance, retention, proof, budget, admissibility, authority/reference, feedback, and integration.

Canonical flow:

```text
Distinction Space
→ Agentic / Decision relevance
→ Projection if addressability is needed
→ Budget / Admissibility if transition is requested
→ Intention if agentic pressure enters decision topology
→ Consent if consequence affects an agentic locus
→ Execution if a permitted branch emits effect
→ Consequence if a target regime changes
→ Feedback / Integration if consequence returns signal
→ Ledger / Provenance if accountable topology must be conserved
→ Retention if persistence or re-entry is needed
→ Proof if stronger status is requested or required
→ Authority / Reference if consequence capacity or future guidance may change
→ LedgerCurvature back into Runtime
```

The lifecycle may loop, branch, skip, defer, quarantine, repair, contest, revoke, archive, or release.

## 11. Regime Lifecycle and Compression

Regime compression must preserve lifecycle role.

A concept should not become a new regime unless it cannot be represented as:

```text
substrate behavior
operator behavior
lifecycle object
regime sub-dynamic
projection handle
budget/constraint effect
```

Core workflow law:

```text
No new regime without burden.
```

If a dynamic can be represented as a sub-dynamic of an existing regime, keep it there.

Examples:

```text
Compression = quarantined compound dynamic, not normal operator/regime.
Interference = runtime phenomenon, not primitive operator.
Stabilization = result/effect, not operator.
Admission = specialized Permit path, not separate root regime.
Commitment = agentic/decision lifecycle dynamic, not support operator.
```
