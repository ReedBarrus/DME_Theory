## 1. Purpose

This document defines the Authority / Reference Ecology of DME V2.

Authority / Reference is a cross-cutting support regime.

It governs:

```text
consequence capacity
authority ceilings
authority classes
reference formation
valid use
invalid use
trust evidence
stake/risk management
revocation
canon posture
modular mechanization boundaries
```

It answers:

```text
What can affect consequence?
What can guide future configuration?
Under what scope?
With what stake?
With what risk?
With what proof support?
With what feedback history?
With what revocation path?
With what modular behavior class?
```

Authority / Reference Ecology is the capstone governance layer because it determines what may become consequential or guidance-bearing after passing through distinction, agency, decision, budget/admissibility, feedback, retention, ledger/provenance, projection, and proof.

---

## 2. Core Thesis

```text
Authority / Reference Ecology is the regime of governed consequence capacity
and future configuration guidance.
```

Compressed:

```text
Authority = scoped, revocable consequence capacity.
Reference = scoped guidance for future configuration.
Canon = governed, durable, revocable reference posture.
TrustEvidence = scoped reliability evidence derived from integrated consequence history.
Revocation = removal or reduction of authority, reference, access, retention, or canon posture.
```

Core law:

```text
Authority determines what may affect consequence.
Reference determines what may guide future configuration.
Neither is final truth.
```

---

## 3. Why Authority / Reference Exists

DME needs a way to distinguish:

```text
what can be seen
what can be remembered
what can be tested
what can be acted upon
what can affect consequence
what can guide future action
what can become durable doctrine
```

Without Authority / Reference Ecology, DME risks collapse such as:

```text
access → authority
trust → authority
proof → authority
retention → reference
recurrence → reference
projection → canon
single success → general permission
ledger record → legitimacy
commitment → authorization
```

Authority / Reference prevents these collapses by requiring scoped consequence capacity, proof support, trust evidence, stake mapping, feedback history, valid/invalid use, and revocation.

## 4. Authority

### Definition

```text
Authority =
scoped, revocable consequence capacity.
```

Authority defines what a locus, process, object, reference, decision branch, tool, or governance body may affect as consequence.

Authority applies to:

```text
agentic loci
tools
workflows
operator paths
decision branches
execution candidates
projection handles
retention echoes
proof results
reference objects
governance processes
```

Authority is not identity.

Authority is not truth.

Authority is not access.

Authority is scoped capacity to affect consequence.

### Non-Claims

```text
authority ≠ truth
authority ≠ agency
authority ≠ identity
authority ≠ access
authority ≠ proof
authority ≠ trust
authority ≠ reference by default
authority ≠ permanence
```

## 11.X Ownership

Definition:

Ownership =
scoped, provenance-backed authority posture over control, use, modification,
exclusion, transfer, benefit, attribution, and stewardship of an object,
contribution, process, memory, or value-flow.

Ownership is a specialized authority state.

Ownership is not identical to authorship, access, custody, stewardship,
benefit, or contribution. These may support an ownership claim but do not
collapse into ownership by default.

Ownership requires:
- provenance support
- contribution or transfer basis
- scope
- consequence class
- valid use
- invalid use
- authority ceiling
- benefit relation
- stewardship obligation, if any
- revocation or dispute path
- governance posture

OwnershipClaim =
claim that a locus has scoped consequence-right over an object,
contribution, system component, memory structure, or value-flow.


OwnershipEnvelope =
AuthorityEnvelope specialized for ownership claims, preserving
authorship, contribution basis, control rights, use rights, modification rights,
exclusion rights, transfer rights, benefit rights, stewardship duties,
valid/invalid use, consequence class, dispute path, and revocation conditions.

## 18. Valid Use / Invalid Use

Reference requires valid and invalid use.

### ValidUse

```text
ValidUse =
declared use context where a reference may guide future configuration.
```

### InvalidUse

```text
InvalidUse =
declared use context where a reference must not be applied.
```

Invalid use is as important as valid use.

It prevents reference from leaking beyond scope.

Examples:

```text
valid: local reversible code edits
invalid: external deployment without review

valid: definition inside DME V2 docs
invalid: treating definition as final scientific fact

valid: repair pattern for similar test failures
invalid: automatic patching without current file inspection
```

Core law:

```text
A reference without invalid-use boundaries is authority risk.
```

## 22. Authority and Budget / Admissibility

Authority depends on Budget / Admissibility but is not the same.

Budget asks:

```text

```

Admissibility asks:

```text

```

Authority asks:

```text
May this locus/process/object affect consequence under this scope?
```

A transition may be budgeted and admissible but still authority-limited.

Non-collapse:

```text
budget ≠ authority
admissibility ≠ authority
permit ≠ authority
authority ≠ permission_by_itself
```
