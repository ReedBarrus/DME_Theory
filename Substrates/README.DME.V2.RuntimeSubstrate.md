## 1. Purpose

This document defines the Runtime Substrate of DME V2.

The Runtime Substrate is the active configuration-attention continuum where admitted distinctions become living topology under finite attention, projection pressure, retention echo, proof tension, authority constraints, and feedback integration.

It answers:

```text
What is active now?
What distinctions are receiving attention?
What localities are forming?
What relations are emerging?
What interference or pressure patterns are observable?
What topology candidates are stabilizing?
What decision pressure is forming?
What should be projected, retained, proof-loaded, released, or routed?
```

The Runtime Substrate does not create truth, authority, canon, or final meaning by itself.

Runtime activates candidates.

Runtime does not crown them.

## 4. Runtime as Four-Pressure Balancing Field

Runtime balances four pressure families.

```text
1. Structural admission pressure
2. Projection-attention pressure
3. Retention / echo pressure
4. Proof / authority tension
```

Together they determine what becomes active, salient, related, projected, retained, proof-routed, decision-relevant, or released.

---

## 4.1 Structural Admission Pressure

Structural pressure enters from the Structure Substrate.

It consists of newly admitted:

```text
DistinctionRegion
StructuralSignature support
DistinctionEvidencePacket support
source-derived recurrence
source-derived rupture
source-derived novelty
```

Structural pressure says:

```text
the source supports this possible distinction
```

It does not say:

```text
this is true
this is meaningful
this should be projected
this should be retained
this should drive consequence
```

---

## 4.2 Projection-Attention Pressure

Projection pressure enters from the Projection / Index / Rasterization Substrate.

It consists of:

```text
ProjectionHandle
ProjectionToken
EmbeddingRegion
SymbolCandidate
DashboardView
AgentReadPacket
LanguageOperatorPacket
user/agent/LLM attention
```

Projection pressure says:

```text

```

It does not say:

```text
this projection is source
this handle is identity
this token is distinction
this embedding is meaning
this view should drive consequence
```

Projection pressure can help coordinate runtime.

It can also over-stabilize weak distinctions.

Therefore, projection pressure must remain provenance-aware and budgeted.

## 4.3 Retention / Echo Pressure

Retention pressure enters from the Retention Ecology and Ledger Substrate.

It consists of:



Retention can support runtime coherence by returning relevant structure.

Retention can also contaminate runtime if stale, weakly provenanced, over-compressed, or over-weighted.

```text
Echo may support activation.
```

## 17. RouteSelection

Runtime routes active topology rather than crowning it.

Possible routes:

```text
ProjectionRoute
RetentionRoute
ProofRoute
DecisionRoute
GovernanceRoute
ReleaseRoute
QuarantineRoute
RepairRoute
```

### ProjectionRoute

Use when topology must become addressable, legible, queryable, or shared.

### RetentionRoute

Use when topology may need persistence, echo, archive, decay, or future re-entry.

### ProofRoute

Use when topology requests stronger status, cross-basis validation, or invariance testing.

### DecisionRoute

Use when topology supports branch formation or consequence-bearing selection.

### GovernanceRoute

Use when topology touches stake, access, consent, authority, reference, or revocation.

### ReleaseRoute

Use when topology is stale, unstable, over-budget, low-support, harmful, or no longer active.

Core law:

```text
Runtime routes candidates.
Other ecologies decide status.
```
