## 1. Purpose

This document defines the Structure Substrate of DME V2.

The Structure Substrate is the read-side entry point where source-native configuration becomes lawful structure capable of supporting distinctions.

It answers:

```text
What source material exists?
What source family does it belong to?
What native configuration does it carry?
What lens or chart can expose it?
What transformations are allowed?
What features or observables can be extracted?
What differences are supported?
What uncertainty and loss were introduced?
What may become a DistinctionRegion?
What may become active runtime?
```

The Structure Substrate does not create meaning, proof, authority, or memory by itself.

It exposes configuration.

It prepares distinction support.

It hands admitted structure to runtime.

---

## 2. Core Thesis

```text
Structure exposes source-native configuration into lawful distinction support.
```

Compressed:

```text
Source emits.
Structure declares, aligns, parses, windows, transforms, compares, extracts, stabilizes,
and admits bounded evidence for distinction.
Runtime activates what structure can support.
Projection addresses what runtime or agents need to navigate.
Ledger records accountable structural transitions.
```

The Structure Substrate is therefore the bridge between:

```text
source-native world
→ configuration topology
→ distinction evidence
→ runtime activation candidate
```

---

## 3. Boundary Law

Structure must preserve the following non-collapse laws:

```text
structure ≠ meaning
structure ≠ truth
structure ≠ memory
structure ≠ proof
structure ≠ authority
structure ≠ projection
source emission ≠ admitted distinction
feature ≠ distinction
signature ≠ identity
language claim ≠ source fact
```

The Structure Substrate may support later meaning, proof, retention, authority, and reference.

It does not produce them by itself.

## 4. Structural Admission Chain

Structural admission is not just ingest.

It is the process by which source-native configuration is declared, provenanced, aligned, transformed, cross-basis tested, feature-extracted, stabilized, and admitted as bounded distinction support before runtime activation.

Canonical chain:

```text
NativeEmission
→ SourceDeclaration
→ ProvenanceEnvelope
→ Normalize / Align
→ Parse / Decode
→ Window / Segment
→ Transform / Chart
→ CrossBasisMap
→ ExtractFeature / Observable
→ Detect / Stabilize
→ StructuralSignature
→ DistinctionEvidencePacket
→ StructuralAdmissibility
→ DistinctionRegion
→ RuntimeActivationCandidate
```

Optional side paths:

```text
CompressionQuarantine
LedgerReceipt
ProjectionEligibility
RetentionEligibility
ProofRoute
```

## 5. Step 1 — NativeEmission

### Definition

```text
NativeEmission = source-local event, signal, payload, utterance, trace, or state emitted before DME transformation.
```

Examples:

```text

audio waveform
JSON object
tool result
file diff

language message
database record
user action

```

NativeEmission is not yet structure.

```text
Under what capture conditions?
With what access/privacy constraints?

```
