## 1. Purpose

This document formalizes the grounded inquiry loop by which DME Theory examines, grounds, and mutates itself.

```text
This is not external methodology applied to DME.

It is DME's own operator grammar and regime lifecycle
executing at the agentic / repository scale,
with humans, LLM assistants, deterministic instruments,
external formalisms, and corpus measurement as
participating loci.
```

---

## 2. Core Thesis

```text
Grounded inquiry =
agentic-scale distinction processing
over the theory's own configuration.

The theory is the source.
The instruments are the admission surface.
The ledger conserves identity through revision.
External mathematics is the constraint topology.
Feedback decides what survives.
Authority decides what becomes canon.
```

## 3. The Protocol Loop

Each stage names its operator-grammar composition, its required artifacts, and its admission discipline.

```text
STAGE 1 - ANCHOR
  operators: Bound + Record
  action: tag the source snapshot before any derived work
  artifact: annotated git tag
  law: derived artifacts without a source anchor have no
       provenance. Tag = ledger anchor, not maturity claim.

STAGE 2 - EXTRACT
  operators: Expose + Differentiate + Record
  action: deterministic admission of source assertions into a
          typed, provenanced claim ledger
  artifacts: extractor, claim inventory, run manifest
  law: extraction evaluates only the axes it can evaluate;
       status ceiling enforced; completeness claimed only over
       the declared grammar.

STAGE 3 - AUDIT
  operators: Compare + Differentiate (judge declared)
  action: sample-based quality evaluation of the instrument
  artifact: audit report with declared judge, seed, and
            per-class verdicts
  law: audit classifications are probabilistic-regime judgments
       and must be declared as such. Blocking analysis separates
       "usable for grounding" from "not safe for compression."

STAGE 4 - PATCH AND MIGRATE
  operators: Repair + Transform + Record
  action: deterministic fixes discovered by audit; ledger
          migration with identity conservation
  artifacts: upgraded extractor, id crosswalk, validation report
  law: every prior entry has a declared fate
       (preserved / merged / superseded). References cited in
       canon must resolve through the crosswalk or the run fails.
       This is conservation through transformation applied to
       the inventory itself.

STAGE 5 - UNPACK
  operators: Compare + Contest (against external topology)
  action: clause-by-clause mapping of a claim cluster against a
          fetched primary definition; counterexample hunting
  artifact: populated FCL entry
  laws: definitions are fetched, never recalled from model
        memory. Admit against definitions; theorem transfer is
        a separate, higher gate. Counterexamples are sought,
        not confirmations. When in doubt: analogical.

STAGE 6 - RAISE
  operators: Contest + Record
  action: convert mapping gaps into Open Doctrine Questions
  artifact: ODQ entries on the ledger
  law: gaps are recorded, never silently patched.
       An ODQ is a branch point in decision space,
       held open until evidence or governance closes it.

STAGE 7 - RESOLVE (conditional)
  operators: Canonize (authority-gated)
  action: doctrine mutation with mandatory resolution_basis
  artifact: doctrine patch citing FCL entries, claim IDs,
            and measurements
  laws: only the authority ceiling for the repository may
        resolve an ODQ into canon. Every resolved law carries
        resolution_basis. Unresolvable-now ODQs stay open;
        openness is a valid terminal state for an iteration.

STAGE 8 - RECURSE
  action: findings feed the next iteration's instruments,
          queues, and targets
  law: each iteration must leave the loop cheaper or sharper:
       a patched instrument, a narrowed gap, a raised priority,
       or a declared dead end.
       Each recursion must update at least one of:
         next_test
         blocked_uses
         ODQ status
         instrument queue
         correspondence queue
         doctrine patch queue
```

## 4. The Three Strata

```text
Layer 1 - Doctrine: what DME currently claims.
Layer 2 - Formal Correspondence Ledger: what appears
          structurally related, with admission status.
Layer 3 - Open Doctrine Questions: what remains unresolved.
```

Movement laws:

```text
observation -> correspondence record    (Stage 5 gate)
correspondence -> admission status      (clause mapping gate)
admission -> doctrine consideration     (ODQ gate)
doctrine consideration -> canon         (authority gate +
                                         resolution_basis)
```

No stratum may be skipped.

Movement is recorded, never inferred.

---

## 5. Agentic Loci and Authority Ceilings

```text
human maintainer:
  canon authority. Resolves ODQs. Owns the repository's
  consequence envelope.

LLM assistants:
  probabilistic-regime loci. Propose, map, judge with declared
  status. May draft doctrine; may not enact it. Their outputs
  are hypothetical topology until instrument-verified or
  authority-adopted.

deterministic instruments:
  admission authority within their declared grammar only.
  May not exceed their status ceiling.

external formalisms:
  constraint topology. They ask questions; they do not
  hold authority over DME canon.

corpus measurement:
  feedback surface. Evidence, not verdict.
```

## 6. Verdict Grammar

Two iterations produced the same outcome shape:

```text
weaker structure:   partially_admitted
stronger structure: analogical
gaps:               converted to ODQs
```

This shape is the protocol's expected healthy output, not a failure mode. A correspondence that admits fully on first unpacking should increase suspicion, not confidence.

---

## 7. Scope Envelope (declared, not hidden)

```text
iterations completed: 2
corpus tested: markdown doctrine (single repository)
correspondence types tested: definitional (order-theoretic,
  categorical)
judges used: single LLM family per role

UNTESTED: code corpora, multi-agent conflict, contested or
adversarial domains, theorem-transfer gates, n > 2 stability.
```

This protocol is feedback-tested within this envelope and projected outside it.

## 8. Non-Collapse Laws

```text
protocol != guarantee
iteration count != truth
verdict grammar stability != correctness
resolution_basis != proof
formal correspondence != identity
formal correspondence != derivation
instrumented recursion != infallible recursion
agentic inquiry != autonomous canon mutation
process doctrine != frozen process
this document != exempt from this document
protocol adoption != protocol validation at new scale
```

## 9. Revision Pathway

This protocol is subject to its own discipline. Each iteration that deviates from it must record the deviation and the reason.

Deviations that recur across iterations are protocol patches in waiting.

The protocol version increments with declared resolution_basis, exactly as doctrine does.
