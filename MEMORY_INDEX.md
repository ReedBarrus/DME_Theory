## 5. Active vs Archive Rules

Active docs define current doctrine.

Archive docs preserve lineage.

Archive docs should be used only for comparison, recovery, or migration support.

If an archived concept appears useful, it should be reintroduced only through the [Agentic_Reasoning/README.DME.V2.ConceptualWorkflowContract.md](Agentic_Reasoning/README.DME.V2.ConceptualWorkflowContract.md).

## 6. Conflict Resolution

Use this priority order when sources disagree:

1. Current user instruction in the active conversation.
2. Current active files in this repo.
3. Current non-archived project memory files.
4. Newly generated files in the active conversation.
5. Archive migration notes.
6. Archived / legacy DME or RIFT documents.
7. Older conversation memory or assistant recollection.

---

## 7. Internal Reference Standards

- Use relative markdown links.
- Prefer links to active docs over archive docs.
- Each major doc should include a `depends_on` list where useful.
- Avoid stale repository names.
- Avoid duplicate references to superseded files unless explicitly marked archive or provenance.
- Use consistent filenames in links.

## 8. Agent Use Contract

- Read this file first.
- Do not treat projection as source.
- Do not treat glossary definitions as schemas.
- Do not treat archive files as active doctrine.
- Do not invent new regimes or substrates.
